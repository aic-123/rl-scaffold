| 我核了什么 | 只核了「来源存在」+「我读到了我声称读到的范围」。**没有复核论文结论是否可复现** |
| 主要局限 | **所有一手来源现在都读到了正文**（2026-09-23 把 DeepSeekMath / Dr. GRPO / DeepSeek-R1 三篇从摘要补到 HTML 正文）。唯一没读全的是 **DAPO**——它的正文只读了四项技术小节与消融数字。逐条范围记在 [`SOURCES.md`](SOURCES.md) |
| ⚠️ 一个自己查出来的漏洞 | 补读时发现：某节点的 `source.ref` 曾声称「§4.1」，而来源清单写「摘要页」——**即引用范围超过了实际读到的范围**。本产品声称守这条纪律，**当时并没有守住**。已登记为欠账，详见 [`SOURCES.md`](SOURCES.md) §七 |

按 Scaffold 的规矩，`已验证` **只能由外部授予**。所以上面那一行不是自谦，是硬约束：
**模型填的东西永远不能标已验证**，这是本结构能成立的前提。

## 它是什么

一个**纯文本、逐行可 diff** 的知识结构，覆盖 RL 工程里那些"会出错的地方"。

> ⚠️ **一个必须说清的现状**：这个仓库**还没有 `git init`**（见 `PLAN.md` §「未做」）。
> 所以"可 git diff"目前是**设计性质**，不是**当前事实**——
> 文本形态确实逐行可 diff，但这里还没有版本历史。
> 已经在 `AUDIT.md` §三 第 10 条登记，**待你拍板**（`git init` 一次即成立）。

- **入口是处境，不是概念**。RL 工程师真实的第一句话不是"我想学 GRPO"，
  而是"**reward 不涨了**"。所以主索引是情境索引（`cues`），不是词条表。
- **分歧只列不裁**。有真分歧的地方（比如"长度增长该归因于什么"）建**议题 + 立场**节点，
  两边都挂上，**不替读者下结论**。
- **来源、机构、置信度一律不进排序**。排序键只有文件路径。
  这是从 Scaffold 继承的硬规矩——否则就是在重造权威垄断。

## 它不是什么

- **不是教程**。不解释基础概念，假定你知道什么是策略梯度
- **不是论文导读**。不摘要论文，只提取"这条知识在什么条件下成立"
- **不是超参推荐表**。不告诉你 β 设多少——那取决于你的任务
- **不做检索服务**。没有搜索引擎、没有索引库、没有服务端。两个视图都是**静态产物**，可以 git diff。
  `tools/find_path.py` 是一个**确定性匹配器**：离线、无模型、可复现，
  给它一句"我遇到的问题"，它返回一条**可行路径**——**不是**一列命中项，也不是一个打分排行
- **不做应用**。`view.html` 是单文件静态渲染，无服务端、无依赖、可离线打开——它不是"一个网站"
- **不收私有配置**。不收公司内部参数、未公开实验结果、付费墙后的内容
- **不给"最佳实践排行榜"**。任何形式的排序、加权、打分都不做。
  **匹配分也一样**：它只衡量文本相近程度，**不衡量可信度**——来源、机构、证据状态在解析阶段就被丢掉，
  打分函数在内存里拿不到它们

## 5 分钟上手

```bash
# 0. 装依赖（只有一条：PyYAML）
python -m pip install -r requirements.txt

# 1. 校验结构自洽（不判断内容对错）
python validator/validate.py ./nodes          # 期望：ERROR 0，退出码 0

# 2. 列出还欠什么
python validator/validate.py ./nodes --todo

# 3. 重建两个视图（改了节点之后跑）
python tools/build_index.py                   # → index/by-situation.md（文本视图）
python tools/render_view.py                   # → index/view.html（渲染视图）

# 4. 检查两个视图是否同序（它们必须是同一份规格的两个形态）
python tools/render_view.py --check           # 期望：退出码 0

# 5. 按需求检索：把你遇到的问题换成一条可行路径
python tools/find_path.py --problem "日志里 entropy 一路往下掉，我不知道要不要停"
python tools/find_path.py --list              # 不匹配，按处境自己找
python tools/find_path.py --check             # 自检（固定用例 + 负例 + 内容断言）

# 6. 缺口采集（方向与 5 相反：不问"我做对了吗"，问"我还差什么"）
python tools/probe_gaps.py                    # 39 句构造语料全量跑
python tools/probe_gaps.py --miss             # 只看没接住的
```

依赖：Python 3.9+ 与 `PyYAML`（与 vendor 来的校验器同一份依赖），列在 `requirements.txt`。
**⚠️ 不装依赖时第 1 条命令就会 `ModuleNotFoundError: No module named 'yaml'`**——
这不是文档疏漏，是这产品"零锁定"的代价，所以第 0 步显式写出来。

**首值路径**：把**你自己遇到的问题**原话丢给 `tools/find_path.py --problem`，
它会匹配一条处境，然后沿 `relations` 走出一条六步路径。
不想匹配就直接打开 [`index/view.html`](index/view.html)——每条处境后面有「看路径」，
点开就是那条处境算好的六步路径。当前 **112 条处境描述 / 36 个节点 / 14 条可行路径**。

## 视图层

Scaffold 的第 ⑥ 层是**视图层**，定义为「**查询/排序规格（可见、可改、可版本化）**」。
本产品按这三条落地：

| 要求 | 落在哪 |
|---|---|
| **可见** | `index/view.html` 顶部直接渲染出排序规格，读页面的人看得见 |
| **可改** | 规格是 `tools/render_view.py` 里的 `SORT_SPEC` 常量，改它就是改视图 |
| **可版本化** | ⚠️ 它在**纯文本**里，逐行可 diff——**但本仓库还没 `git init`**（见 `AUDIT.md` §三 第 10 条），所以"可版本化"目前是设计性质 |

**核心那条规矩**：**排序键只有「文件路径，然后 cue 文本」**。
来源、机构、证据状态、填充者**一律不进排序**，也不加权、不打分。
→ 理由：**排序即推荐**。把权威度写进排序，就是在替读者决定该信谁。

**两个视图，一份规格**：`by-situation.md`（文本）与 `view.html`（渲染）必须给出**逐条一致**的顺序。
这条不变量由 `python tools/render_view.py --check` 强制检查——
**它不能只写在注释里**，因为两个生成器一旦各写各的排序，会**静默地**给出不同顺序。

`--check` 现在还核这三件事（都实测过负例）：

- **「看路径」与判断点严格对应**——是判断点的 cue 必须有、不是的必须没有
- 链接的 **`href` 与 `data-open` 两个属性**都要指向同一个真实存在的路径块
  （只查一个不够：JS 用的是 `data-open`，改坏它会让用户点开**别人的**路径）
- **标签配平**——上一轮生成器多输出一个 `</div>`，页面看起来完全正常，
  因为**浏览器静默容错**。数标签才发现。→ **浏览器容错不是正确。**

**`view.html` 里那个过滤框只隐藏、不重排**：过滤前后顺序完全一致，
它**不是检索功能**，只是显示层的便利。

## 按需求检索：从「我遇到的问题」到一条可行路径

平面索引的毛病是：**你得先知道自己在找什么，才找得到**。
`tools/find_path.py` 补的是另一半——从你嘴里的话走到一个入口，再沿 `relations` 走出一条链。

```bash
python tools/find_path.py --problem "我的模型回答越来越长，token 消耗翻了好几倍"
```

六步路径，每一步都有它存在的理由：

| 步 | 回答什么 | 从哪来 |
|---|---|---|
| ① 先看什么 | 把哪几个量翻出来 | 判断点的 `变量：` 行 + 正文里带数值的判据 |
| ② 为什么（机制） | 底层是什么在起作用 | `概念`。直连优先；没有直连就走议题/例外转一手，**并标注是间接的** |
| ③ 什么情况下不成立 | 这套什么时候别信 | `例外`（出边 + 入边都算） |
| ④ 这背后有没有争论 | 这里是不是有两派 | `议题` → `立场` → `论据` → `案例`（图上 ≤2 跳） |
| ⑤ 别人怎么做的 | 谁真跑过、跑出什么 | `案例`，**按挂载强度分三级**：直接 / 经论据 / 经概念·弱 |
| ⑥ 接下来可能撞上 | 下一步会撞到什么 | 共享概念的其它判断点，标注经由谁 |

### 检索规格（改它就在 `tools/find_path.py` 的 `MATCH_SPEC` 里改）

- **匹配键**：处境句（`cues`）+ 标题 + 别名。
  ⚠️ **`scope` 的中文正文不参与打分**——它只贡献其中的**拉丁标识符**（如 `grad_norm`）。
  旧版这里写着"+ 适用范围"，读起来像 scope 全文参与匹配，**那是虚的**。
  （为什么不让它全文参与：scope 里含「**不适用于…**」的表述，参与匹配后**恰恰会在查询落进
  排除范围时把该节点抬得更高**——方向是反的。已改为在输出里**主动印出**那句排除条件。）
- **算法**：中文按字符二元组重合；英文/数字标识符按 token 集合精确命中，**按稀有度加权**——
  命中罕见的 `grad_norm` 是强证据，命中烂大街的 `kl` 不是
- **标识符是乘不是加**：它**放大已有的文本重合**，不单独加分。
  加法会让一个常见词把"与查询零文本重合"的节点也抬过阈值，等于让一个词替读者决定看哪个节点
- **入口优先判断点**：若最高分不是判断点、而某个判断点也够得着，改判给判断点，
  并**把改判这件事打印出来**。依据是 [`ADAPT.md`](ADAPT.md) §一 已记在案的决议
- **阈值 0.30**。低于它**如实说「没匹配上」**，并列出最接近的几条让你自己挑。
  **不猜、不兜底、不硬凑一个答案给你**

### 两条由代码结构保证的红线

**一、来源与证据状态在解析阶段就被丢掉。**
`_match_record()` 只放行 `id / type / title / aliases / cues / scope / relations`，
`source`、`evidence_status`、`filled_by` **在内存里根本不存在**。
→ 所以"来源不进匹配"不是一句承诺，是打分函数**拿不到它们**。`--check` 会实测这一点。

**二、模糊匹配只有一处实现。**
`view.html` 里**不重复实现打分**——两个实现必然漂移，而漂移的正是顺序。
浏览器里只有：字面过滤 + 点开一条**已经算好**的路径。

### 检索自检（`--check`）钉住七件事

1. 匹配记录里没有来源/证据状态字段（且实测 `_match_record` 真的丢了它们）
2. 每条路径引用的节点都存在（无悬挂 id）
3. 每个判断点都能给出 ①，且 ②/④ 不同时为空（否则它不配当入口）
4. **22 条固定用例全部命中，含 2 条负例 + 3 组内容断言**
   （"今天天气怎么样"必须说没匹配上）
5. **每个判断点的「怎么确认」都读得到**，且每一步不是被换行截断的半句话
6. ⭐ **每个判断点都读得出 ≥1 步「怎么确认」**（2026-09-23 新增）
   —— 旧版只断言 ① 非空，而 ① 非空靠的是 `变量：` 行；
   实测把 `judge-0005` 的整个 `## 怎么确认` 删掉，`--check` **依然退出码 0**
7. ⭐ **有 `scope` 的节点，适用范围必须印进文本输出**（2026-09-23 新增）
   —— 旧版渲染里一个字都不印，于是会给出**明确不适用**的答案而用户看不见

`tools/render_view.py --check` 另有第 8 条：**每个路径块里必须印出该节点的适用范围**。

> **一个只有注释守护的纪律不是纪律，是愿望。**
> 所以匹配质量是靠一张固定用例表钉住的，不是靠"我觉得还行"。
> 实测过负例：把阈值调低后自检确实退出码 1。
> **第 6、7 条是同一句话的第二次应验**：它们**各自都实测过负例**——
> 删掉那一节、拿掉那段输出，检查都会红并**点名具体节点**。
> 一条检查如果没有"已知会报错的输入"，它就不是检查，是装饰。

**一张表，两种条目**（这一条是被一次外部考验撞出来的）：

| 条目 | 断什么 | 证明什么 |
|---|---|---|
| **只断入口的**（多数） | 这句话该送到哪个节点 | 已有的入口**还找得到**（回归） |
| **还带内容断言的**（少数） | 路径里**该出现的内容有没有出现** | **覆盖** |

**入口齐不齐，只能靠第二类来撞。** 自己照节点编的句子只能证明自洽。

⚠️ **但不为外部用例另开一层。** 「如果遇到这种情况怎么办」**就是症状口吻的一种说法**，
走的就是正常检索——给它单开一张表、单开一个命令，等于把已有的入口包装成新类别。
外部用例的"外来身份"写在 `说明` 一栏就够了。

`--problem` 只输出文本。路径的 HTML 形态在 `index/view.html`，
两个形态共用 `find_path.build_path()` 这**一个**模板。

### ⚠️ 主入口是补上来的，不是一开始就有的

`PLAN.md` §一 第一句就写着「一个 RL 工程师的真实入口不是『我想学 GRPO』，
而是**『reward 不涨了』**」。**而第一版 75 条处境里，一条都不是它。**

它是被一次**外部场景**撞出来的：对方举出一个考验用例（「如果遇到这种情况，你的系统怎么办」），
拿它去检索，结果是这样——**这是补入口之前的实测**：

```
reward 曲线跑着跑着崩了
  0.48 con-0006   cue=0.000   title=0.000   alias=0.385   ids=['reward']
```

`cue` 重合 **0.000**、`title` 重合 **0.000**——这句话和结构里**任何一条处境描述、
任何一个标题都没有字面重合**，它是靠"句子里出现了一个叫 `reward` 的词"才落下来的。

**为什么自检没抓到**：`SELF_TEST` 里的用例都是照着**已有节点**写的，
所以它只能证明"已有的入口都能被找到"，**证明不了"入口齐了"**。

> **用自己造的用例测自己的系统，测的是自洽，不是覆盖。覆盖要靠外部场景来撞。**

补法见 [`ADAPT.md`](ADAPT.md) §十二：新增 `judge-0009`（**分诊**判断点），
把「reward 崩了」拆成四条可分别去查的方向，并给出**怎么确认**的方法。

### ⚠️ 而这道题还撞出了第二个缺口：① 只给"看什么"，不给"怎么看"

那道题的后半句是「审计到有 50% 的 rollout 推对了却给了 0 分」。
系统当时能说出**「假阴性率」这个名字**，却**不说这个数怎么得到**——
**而 `judge-0009` 的正文里明明写着四步怎么测。**

原因：路径模板的 ① 只取 `变量：` 行 + 带数值的判据行，**不收正文的「怎么确认」节**。

→ ① 改成三段：**变量（看什么）→ 怎么测（怎么看）→ 判据（到什么程度算数）**。
理由一句话：**一个测不出来的变量等于没给。**

**⚠️ 但修模板只解决了一半。** 数了一下：**9 个判断点里只有 `judge-0009` 写了那一节。**
所以另外 8 条的 ① 当时仍然"只给量名不给测法"。

→ 已给**其余 8 个判断点补上「怎么确认」**（每个 3–4 步，共 28 步）。
三条纪律：**每一步都要能回到来源**；来源没给方法的（如 judge-0001 第 3 步、
judge-0002 第 1 步）**要标出来源强度**，不能混在"论文说的"里；
**判断点里也有"不是排查题"的**（`judge-0005` 是选型题，它的"怎么确认"是
"先确认你手上是哪种实现"），**不硬套同一个形状**。

### ⚠️ 第三件事：那道题**不是案例**

对方举这个例子，是**考验**系统遇到这种情况会怎么办——**它是一道题，不是一个事实记录**。

曾把它建成了 `case-0006`（案例位，正文留空等使用者填）。**已删除**，理由：

> **案例不能由举例生成。** 留一个空壳案例位，等于给「看起来有案例」留了个假证据。

**而它也不需要新家。** 「如果遇到这种情况怎么办」**就是症状口吻**——
走的就是普通检索命令，本来就掉不出去。它现在是一条**带内容断言的用例**，
留在 `SELF_TEST` 里。

> ⚠️ 我一度给它单开了一张表（`SCENARIO_TEST`）和一个命令（`--scenario`）。
> **那是把一个已有的入口包装成了新类别**——已并回 `SELF_TEST`。
> 详见 [`ADAPT.md`](ADAPT.md) §十三。

### 分诊节点：`judge-0009`

| 你看到的 | 大概是什么 | 去看 |
|---|---|---|
| 奖励是 0，但推理看起来是对的 | 判分规则没匹配上（最常见：答案被截断） | `judge-0004` |
| 一批 prompt 的奖励全是 1（或全是 0） | 组内无方差 → 优势为 0 → 白跑 | `judge-0002` |
| 判分依赖格式，格式又依赖长度 | 奖励函数把「格式对不对」和「答案对不对」绑成了一件事 | `con-0006` |
| 上面都排除了 | 不在奖励侧，去看熵与训练-推理偏差 | `judge-0001`、`judge-0006` |

**它和 `judge-0004` 的区别**：`judge-0004` 问的是「截断样本的奖励怎么给」——
那是**已经知道问题出在截断**之后才问得出来的问题。
真实的第一句话是「reward 崩了」，这时候你还不知道原因。

**这是本结构里唯一一个 `source.kind: 其他` 的节点**——它不引入任何新事实，
只引入**路由**；分诊依据全部来自它指向的节点。详见 [`ADAPT.md`](ADAPT.md) §十二。

## 已知的未做（不是漏了）

| 没做 | 理由 |
|---|---|
| 检索服务 / 索引库 | 没有搜索引擎、没有数据库、没有服务端。检索是一个**离线确定性匹配器**（`tools/find_path.py`），无模型、可复现、可自检。`view.html` 里的过滤框**只隐藏不重排**，不构成检索 |
| 用模型做匹配 | **明确不做。** 模型提名入口 = 一种不可复现、不可核对的"自称"，和本产品「`evidence_status` 不能自称已验证」是同一类问题；模型给候选打分 = 让不透明的东西进了排序。匹配只用确定性算法，**匹配不上就如实说匹配不上** |
| 应用型 Web UI | `index/view.html` 是**单文件静态渲染**，无服务端、无依赖、可离线打开。**不是**一个应用——没有后端、没有状态、没有账号 |
| 扩节点类型 | 扩类型要改 Scaffold 的 schema。本产品**不改上游** |
| 引入二手来源 | 本产品定下的门槛是"只收能给出稳定标识且我读过的"。二手来源的约定已写在 `SOURCES.md` §四，**尚未触发** |
| 收录配置项 / 推荐值 | 见 [`ADAPT.md`](ADAPT.md) §三。连论文自己的干预比例也只作为"该论文的实验设置"记录，不写成推荐值 |
